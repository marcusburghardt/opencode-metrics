## ADDED Requirements

### Requirement: Dimensional Database Schema

The metrics database SHALL use a dimensional model with separate
dimension tables (sessions, projects) and a fact table (measurements).
A metric_definitions catalog table SHALL describe every metric stored
in the database. All table creation statements SHALL use IF NOT EXISTS
to ensure idempotency.

#### Scenario: Schema supports new metrics without migration

- **GIVEN** the database schema is initialized with v1 metrics
- **WHEN** a future plugin version adds a new metric (e.g.,
  tokens_search)
- **THEN** the new metric SHALL be added as new rows in
  metric_definitions and measurements
- **AND** no ALTER TABLE or schema migration SHALL be required
- **AND** existing data SHALL remain intact and queryable

#### Scenario: Grafana SQL queries work against the schema

- **GIVEN** the database contains session metrics
- **WHEN** a user queries daily cost with:
  SELECT date(recorded_at/1000, 'unixepoch') as day,
  SUM(value) as cost FROM measurements
  WHERE metric_name = 'cost' GROUP BY day
- **THEN** the query SHALL return valid time-series data

### Requirement: Concurrent Write Safety

The metrics database SHALL operate in WAL journal mode with a
busy_timeout of 5000ms. Write operations SHALL be wrapped with
application-level retry logic (3 attempts, exponential backoff).
All writes for a single idle event SHALL be wrapped in a single
transaction.

#### Scenario: Two instances write near-simultaneously

- **GIVEN** two OpenCode instances are running with the plugin
- **WHEN** both sessions transition to idle within milliseconds of
  each other
- **THEN** both writes SHALL succeed (one queues behind the other)
- **AND** no data SHALL be lost or corrupted
- **AND** each session's metrics SHALL be recorded correctly

#### Scenario: Write contention exceeds busy_timeout

- **GIVEN** an OpenCode instance attempts to write metrics
- **WHEN** the database is locked beyond the 5000ms busy_timeout
- **THEN** the write SHALL be retried up to 3 times with exponential
  backoff (100ms, 200ms, 400ms)
- **AND** if all retries fail, the error SHALL be logged but the
  plugin SHALL NOT crash

### Requirement: Transaction Atomicity

All database writes for a single session idle event SHALL be wrapped
in a single transaction. If any write within the transaction fails,
the entire transaction SHALL be rolled back.

#### Scenario: Partial write failure

- **GIVEN** a session transitions to idle
- **WHEN** the project upsert succeeds but a measurement insert fails
- **THEN** the entire transaction SHALL be rolled back
- **AND** the database SHALL remain in a consistent state
- **AND** the error SHALL be logged

### Requirement: V1 Metric Catalog

The metric_definitions table SHALL be seeded with the following metrics
on database initialization:

| metric_name | unit | description | aggregation |
|---|---|---|---|
| cost | usd | Total session cost in USD | sum |
| tokens_input | tokens | Non-cached input tokens sent to the model | sum |
| tokens_output | tokens | Output tokens generated by the model | sum |
| tokens_reasoning | tokens | Reasoning tokens consumed by the model | sum |
| tokens_cache_read | tokens | Input tokens served from prompt cache | sum |
| tokens_cache_write | tokens | Input tokens written to prompt cache | sum |
| cache_hit_ratio | ratio | Fraction of input tokens served from cache | avg |
| duration_seconds | seconds | Wall-clock session duration in seconds | sum |
| files_changed | count | Number of files changed in the session | sum |
| lines_added | count | Lines added across all file changes | sum |
| lines_deleted | count | Lines deleted across all file changes | sum |
| messages_total | count | Total messages exchanged in the session | sum |

#### Scenario: Metric catalog is self-describing

- **GIVEN** the database is initialized
- **WHEN** a user queries SELECT * FROM metric_definitions
- **THEN** every metric stored in the measurements table SHALL have
  a corresponding entry in metric_definitions with its unit,
  description, and recommended aggregation type

### Requirement: Timestamp Convention

All timestamp fields in the database (started_at, ended_at,
recorded_at) SHALL store Unix epoch milliseconds as INTEGER values.

#### Scenario: Grafana time-series queries use millisecond timestamps

- **GIVEN** the database contains measurement records
- **WHEN** a user queries with `date(recorded_at/1000, 'unixepoch')`
- **THEN** the query SHALL return correct date values because
  recorded_at stores milliseconds since Unix epoch

### Requirement: Schema Versioning

The database SHALL track its schema version using SQLite's
`PRAGMA user_version`. The version SHALL be set to 1 on initial
creation. On each startup, the plugin SHALL read the schema version
and apply any necessary migrations for older schema versions before
proceeding with normal operation.

#### Scenario: Future schema migration

- **GIVEN** a database created with schema version 1
- **WHEN** a future plugin version requires schema version 2
- **THEN** the plugin SHALL detect the version mismatch on startup
- **AND** SHALL apply the version 1 to version 2 migration
- **AND** SHALL update PRAGMA user_version to 2 after migration

### Requirement: Derived Metric Formulas

The following metrics SHALL be computed from SDK session data rather
than stored directly:

- `cache_hit_ratio`: computed as
  `tokens_cache_read / (tokens_cache_read + tokens_input)`.
  When the denominator is zero, the metric SHALL be recorded as 0.
- `duration_seconds`: computed as
  `(time_updated - time_created) / 1000`.
  When either timestamp is missing or the result is negative, the
  metric SHALL be recorded as 0.

#### Scenario: Division by zero in cache_hit_ratio

- **GIVEN** a session has tokens_cache_read = 0 and tokens_input = 0
- **WHEN** the session metrics are computed
- **THEN** cache_hit_ratio SHALL be recorded as 0
- **AND** no NaN or null value SHALL be written to the database

#### Scenario: Missing timestamps in duration computation

- **GIVEN** a session has time_created but time_updated is null
- **WHEN** the session metrics are computed
- **THEN** duration_seconds SHALL be recorded as 0
